# POPQ Flutter 9단계 실행 계획

## 구현 순서

Flutter는 소비자 앱을 먼저 구현하고 판매자 앱으로 확장한다. 현재 `mobile_flutter`는 기본 템플릿 수준이므로 기능 구현 전에 두 앱과 공유 패키지의 경계를 먼저 만든다.

```text
mobile_flutter/
├─ apps/
│  ├─ customer_app/
│  └─ seller_app/
└─ packages/
   ├─ app_core/
   └─ design_system/
```

- `customer_app`: 회원용 검색·스토어·상품·주문·리뷰·마이페이지
- `seller_app`: 스토어 운영·상품 품절·주문 처리·기본 매출
- `app_core`: API envelope, 인증 토큰, 네트워크 오류, 로깅, 공통 모델의 최소 계약
- `design_system`: 색상·타이포그래피·간격·버튼·입력·로딩·빈 상태

도메인 화면과 상태 관리는 앱별로 둔다. 소비자와 판매자 기능을 공유 패키지에 섞지 않는다.

## 백엔드 선행 계약

현재 백엔드는 QR 비회원 주문과 판매자 운영 API가 중심이다. Flutter 소비자 앱에는 다음 API가 추가로 필요하다.

- 회원 OAuth/Firebase 토큰 교환, Access/Refresh Token 갱신
- 위치·키워드·태그 기반 공개 스토어 검색과 상세 — 9.2 완료
- 회원 주문 생성·결제·내역·상세·상태 동기화 — 9.3 완료
- 관심 스토어 — 9.4 완료
- 리뷰 작성·수정·삭제·목록과 마이페이지 집계 — 9.4 완료
- FCM 토큰 등록·해제와 알림 딥링크 payload — 9.5 REST 기반 완료, Firebase 연결 대기

각 기능 단계에서 필요한 Spring Boot API를 추가한 뒤 실제 저장소 구현과 계약 테스트로 교체한다. 9.2 소비자 탐색, 9.3 상품·주문, 9.4 관심·리뷰·마이페이지는 실제 API 저장소로 연결했고 위젯 테스트에는 메모리 저장소를 주입한다.
