# POPQ 웹 후속 백로그

## 기준선

- `web_react/popq`는 로그인 없는 QR 고객 주문 웹이다. 회원용 검색·관심·리뷰 기능은 이 웹에 추가하지 않고 Flutter 소비자 앱에서 구현한다.
- `web_react/seller-web`은 주문·상품·QR·매출 요약·스토어 설정·기본 관리자 운영 MVP를 완료했다.
- 아래 항목은 Flutter 앱 개발을 막지 않는다. 해당 우선순위가 시작될 때 백엔드 계약부터 다시 확인한다.

## P0 — 웹 공개 운영 전 필수

| ID | 목표 | 현재 차이 | 완료 조건 |
|---|---|---|---|
| WEB-01 | 판매자 인증·세션 | 스토어 ID와 Access Token을 수동 입력 | OAuth 로그인, 토큰 갱신, 로그아웃, 담당 스토어 선택이 UI에서 완결 |
| WEB-02 | 인증·권한 오류 처리 | 기능별 API 오류 표시는 있으나 공통 세션 복구 계층 없음 | `401` 갱신 1회, `403` 권한 안내, 만료 시 로그인 복귀를 공통 처리 |
| WEB-03 | 판매자 가입·검증 | 개발 로그인과 기존 판매자 토큰을 전제 | 사업자/행사 판매자 신청, 검토 상태, 반려 사유 화면 제공 |
| WEB-04 | 웹 CI 품질 게이트 | 로컬 Vitest·lint·build·Playwright 검증 | PR마다 두 웹의 test, lint, production build, 핵심 E2E 자동 실행 |

## P1 — 운영 기능 확장

| ID | 목표 | 완료 조건 |
|---|---|---|
| WEB-05 | 스토어 멤버·권한 | 초대, 역할 변경, 해제 및 OWNER/MANAGER/STAFF별 UI 제한 |
| WEB-06 | 정산 상세 | 기간별 정산 예정·완료·공제 내역과 내보내기 |
| WEB-07 | 관리자 운영 확장 | 주문·결제·환불·보상 처리 조회와 조치 이력 |
| WEB-08 | 감사 로그 | 관리자 및 스토어 주요 변경의 행위자·시각·대상 조회 |
| WEB-09 | 공지·고객 소통 | 공지 작성·노출 기간·대상 채널 관리 |

## P2 — 후속 고도화

| ID | 목표 | 완료 조건 |
|---|---|---|
| WEB-10 | 판매자–고객 채팅 | 주문 단위 대화, 보존 정책, 신고·차단 정책 포함 |
| WEB-11 | 접근성·브라우저 QA | 키보드 탐색, 스크린리더 레이블, 명암, 지원 브라우저 회귀 검증 |
| WEB-12 | 운영 관측성 | 프런트 오류 수집, 배포 버전 식별, 핵심 전환 지표와 알림 |

## 재개 규칙

1. P0는 웹 외부 공개 또는 실제 판매자 계정 연동 전에 재개한다.
2. P1은 Flutter 소비자 앱의 핵심 주문 흐름이 안정화된 뒤 우선순위를 다시 정한다.
3. P2는 실제 운영 데이터와 고객지원 요구를 근거로 착수한다.
